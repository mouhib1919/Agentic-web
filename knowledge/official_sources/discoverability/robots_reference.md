# Robots Exclusion Protocol (robots.txt)

## Overview

The Robots Exclusion Protocol is a convention that allows a website to communicate crawling permissions to automated clients — search engine crawlers, archival bots, and other software agents — before they request any other resource on the site. The convention is implemented through a single plain-text file, `robots.txt`, published at the root of a web origin.

## Official Definition

The protocol is formally standardized by the IETF in RFC 9309, "Robots Exclusion Protocol" (September 2022), which codifies behavior that had existed as a de facto web standard since 1994. RFC 9309 defines the file location, syntax, parsing rules, and precedence logic that a conforming crawler must implement. It does not grant or enforce access control; it is an advisory mechanism that well-behaved clients are expected to honor voluntarily.

## Core Concepts

- **User-agent groups**: Rules are organized into groups, each beginning with one or more `User-agent` lines identifying the crawler(s) the group applies to, using either an exact product token (e.g. `Googlebot`) or the wildcard `*` for all crawlers not matched by a more specific group.
- **Allow / Disallow directives**: Within a group, `Disallow` lines specify URL path prefixes the named crawler should not fetch; `Allow` lines specify exceptions that override a broader `Disallow`.
- **Longest-match precedence**: When multiple `Allow`/`Disallow` rules could match a given path, RFC 9309 specifies that the rule with the longest matching path prefix wins; ties are broken in favor of `Allow`.
- **Sitemap directive**: An optional `Sitemap:` line may appear anywhere in the file, providing the absolute URL of one or more sitemap files, independent of any `User-agent` group.
- **Crawl-delay**: A non-standardized but widely supported directive requesting a minimum interval, in seconds, between successive requests from a crawler.

## Technical Details

- Location: must be served at `/robots.txt` relative to the origin (scheme + host + port); rules do not apply across different origins or subdomains.
- Encoding: UTF-8 plain text.
- Response requirements: RFC 9309 specifies that a 200 response is parsed as rules; a 4xx response is treated as "no rules apply, full access allowed"; a 5xx response causes conforming crawlers to assume full disallow until the file becomes available; unreachable/network-error responses are handled per crawler-specific policy.
- Line syntax: `field: value`, one directive per line; `#` begins a comment; matching of paths is case-sensitive and supports the wildcard characters `*` (any sequence) and `$` (end of path anchor).
- Maximum file size: RFC 9309 recommends crawlers parse at least the first 500 kibibytes and may ignore content beyond that limit.

## Detection Characteristics

- Presence of a file at `/robots.txt` returning HTTP 200 with `Content-Type` typically `text/plain`.
- Contains one or more `User-agent:` blocks with `Allow:`/`Disallow:` directives.
- May contain a `Sitemap:` directive referencing an absolute sitemap URL.
- Absence of the file, a non-200 status other than 404, or an empty body are all distinct, detectable states with different crawler implications.

## Common Implementations

- Static file served directly by the web server or CDN.
- Dynamically generated by the application framework based on environment (e.g., disallowing all crawling on staging deployments).
- Frequently references one or more XML sitemaps via the `Sitemap:` directive.
- Often includes explicit rules for known crawlers (search engines, SEO tools, AI training/browsing agents) in addition to a default `User-agent: *` group.

## Limitations

- Advisory only: it does not prevent access, only requests that compliant clients refrain from crawling specified paths; it provides no authentication or authorization.
- Does not control indexing directly — a disallowed URL can still appear in search results (without content) if discovered through external links; the `noindex` meta directive or HTTP header serves that purpose instead.
- Scope is limited to a single origin; a multi-subdomain site needs a `robots.txt` per subdomain.
- Rule precedence and wildcard support vary slightly between crawler implementations predating RFC 9309's formalization.

## Related Technologies

- Sitemaps protocol (referenced via the `Sitemap:` directive)
- `X-Robots-Tag` HTTP header and `<meta name="robots">` HTML tag (indexing control, distinct from crawl control)
- `llms.txt` convention (AI-agent-oriented content index, not a crawl-permission mechanism)
